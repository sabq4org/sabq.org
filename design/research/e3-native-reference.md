# تقرير الاستكشاف E3 — أنماط UX في iOS وAndroid (مرجع)

> المصدر: مدقق_المرجع_الأصلي. الأدلة بصيغة path:line.

## ملاحظة تأسيسية
الموبايل **لا يستخدم `/api/ai/daily-summary`** — يبني الموجز من حالة محلية (بروفايل + محفوظات + كاش). الويب مبني على الـ API بالكامل. المنتجان مختلفان جوهرياً تحت نفس الاسم؛ نستعير الأنماط لا البنية.

## (1) ترتيب الأقسام في iOS (المرجع)
**وضع العضو** (`DailyBriefView.swift:72-81`):
1. Member Hero — أفاتار + اسم + دور + إيميل (تدرج خفيف + ultraThinMaterial)
2. Stats Row — 3 بلاطات: «محفوظ» / «اهتماماتك» / «يوم معك» (عمر العضوية)
3. Interests Card — chips + زر «تعديل» أو حالة فارغة مع CTA
4. Suggestions — شريط أفقي «اقتراحات لك»، **يُخفى كلياً عند غياب المحتوى**
5. Mood Card — بطاقة مدمجة: أيقونة + «مزاجك القرائي اليوم» + **سطر تفسيري**

**وضع الضيف**: Hero تعريفي → شبكة قيم 2×2 → معاينة اهتمامات → مزايا «بعد التسجيل تحصل على» → CTAs تسجيل/دخول (`DailyBriefView.swift:454-462`).

Android نسخة 1:1 معلنة (`DailyBriefScreen.kt:69`).

**مقارنة:** الويب data-first (KPIs أولاً)، الموبايل people-first (الهوية أولاً، المزاج ختاماً ناعماً).

## (2) التفاعلات
- لا pull-to-refresh (بيانات محلية)؛ الويب: زر تحديث يدوي + أيقونة دوّارة.
- InterestsPicker: عدّاد اختيارات متدرج اللون + «حدد الكل»/«امسح الكل» + شريط حفظ ديناميكي النص («حفظ N تصنيف»/«تخطّي الآن»).
- Skeleton أثناء التحميل + حالة فارغة بزر «إعادة المحاولة».
- تسخين كاش التصنيفات مسبقاً حتى يفتح الـ picker فورياً.

## (3) عناصر في الموبايل تفتقدها نسخة الويب
1. **وضع الضيف التسويقي** — الويب يعرض بطاقة خطأ جامدة؛ iOS يقدم landing كاملة.
2. **إدارة الاهتمامات داخل الصفحة** (chips + تعديل + picker).
3. **بلاطة «يوم معك»** — عمر العضوية بالأيام (لمسة ولاء).
4. **بطاقة المزاج المدمجة مع سطر تفسيري** — الويب يعرض المزاج مرتين مفككاً بلا تفسير.
5. **شريط اقتراحات أفقي بصور** — اقتراحات الويب نصية بلا صور.
6. **الإخفاء الشرطي النظيف** للأقسام الفارغة.
7. **«لا شاشة فارغة أبداً»** — graceful degradation بدل سقوط الصفحة كاملة.

## (4) فروق iOS ↔ Android (تقنية طفيفة)
blur حقيقي مقابل شبه شفاف، picker كـ sheet مقابل شاشة، رسالة فشل حفظ inline في أندرويد فقط، haptics في iOS فقط، FocalCachedAsyncImage في أندرويد.

## توصيات مستخلصة للويب
1. تبنّي وضع ضيف على نمط iOS بدل بطاقة الخطأ.
2. إعادة ترتيب الصفحة people-first: تحية/هوية → إحصاءات شخصية خفيفة → اهتمامات → اقتراحات → مؤشرات ثقيلة مطوية افتراضياً.
3. توحيد المزاج في بطاقة واحدة مدمجة مع سطر تفسيري.
4. اقتراحات ببطاقات مصوّرة (imageUrl متوفر في الـ API) + إخفاء القسم عند غيابها.
5. عند فشل الـ API: تدهور رشيق (أقسام من بيانات بديلة) بدل سقوط كامل.
