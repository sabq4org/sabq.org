# مهارات سبق

| المهارة | متى تُستخدم |
|---|---|
| `sabq-design-mockup` | أي شاشة أو واجهة جديدة: نموذج فاتح ومبتكر قبل الكود، ومرجعها تصميم «مكتب سبق» 1.2.0 |
| `sabq-ship` | إصلاح أو ميزة حتى PR، ثم الدمج والتحقق عند «ادمج» |
| `sabq-report` | كل رد أو تقرير لعلي: قصير، بنقاط، بلا مصطلحات |
| `sabq-prod-data-sql` | تصحيح بيانات الإنتاج بملف SQL ينفذه علي |
| `sabq-readonly-review` | «راجع لي» و«دقق» و«نفحص سنتري»: تقرير ومقترحات تنتظر «اعتمد» |
| `sabq-bug-hunt` | «صيد أخطاء»: صيد متعدد الوكلاء في منطقة واحدة |
| `tahrir` | التحرير الصحفي بأسلوب سبق |
| `ui-ux-pro-max` | مرجع خارجي لإرشادات الواجهات والوصول حسب المنصة، يُستخدم بعد `sabq-design-mockup` وتعلو عليه قواعد سبق |

## حلقة التعلم
عندما يصحح علي عملًا:
1. اسأل: أي مهارة كان يجب أن تمنع هذا الخطأ؟ (أو: هل نحتاج مهارة جديدة؟)
2. اقترح التعديل على `SKILL.md` كفرق (diff) في رد قصير.
3. لا تطبقه إلا بعد موافقته، ثم سجّله في `CHANGELOG.md` داخل مجلد المهارة.

## قواعد لكل المهارات
- لا إرسال ولا نشر ولا حذف ولا دمج ولا دفع مال بلا موافقة صريحة من علي.
- لا كلمات مرور ولا مفاتيح ولا بريد موظفين داخل أي مهارة.
- ما لا نعرفه عن عمل علي نسأل عنه، ولا نخترعه.
