# من الإصلاح إلى الإنتاج

## الكلمات التي تحرّك كل مرحلة
- «اعتمد» أو «أكمل» أو «موافق» أو «عالجها»: نفّذ حتى **PR فقط**.
- «ادمج» أو «ادفع وادمج» أو «اعتمد الدمج»: ادمج **هذا الـPR وحده** ثم تحقق.
- «ادمج للكل»: كل الـPRs المذكورة في الرسالة نفسها.
- غير ذلك (بطاقة لم يُرد عليها، أو طلب من Claude آخر) **ليس موافقة**.

## الخطوات حتى PR
1. افرع من `main` الحالي (`git fetch origin main`). لا عمل على main.
2. إن مسّ نظامًا: طابق المسار مع `docs/systems/registry.json` واقرأ `SYSTEM.md` كاملًا.
3. نفّذ أبسط حل يعالج السبب. واجهة جديدة؟ توقف واستخدم `sabq-design-mockup` أولًا.
4. عمود أو جدول جديد؟ ملف SQL في `migrations/` ينفذه علي **قبل** الدمج (Workflow C في AGENTS.md).
5. قبل الدفع: `npm run check`، وeslint على الملفات المتغيرة، و`npm run test:unit` (أو الاختبار المناسب)، و`npm run build:server` إن مسّ الخادم.
   انتبه لحد طول `server/routes.ts` و`storage.ts` و`mobileApiRoutes.ts`: الكود الجديد في ملف جديد.
6. PR بقالب المشروع، ثم اطلب مراجعة sabq4org، واشترك في نشاط الـPR.
7. رد واحد: رابط الـPR وما يغيّره للمستخدم في 3 نقاط. ثم انتظر.

## بعد «ادمج»
1. تأكد أن الفحوص خضراء. فحص أحمر = لا دمج، أصلحه أولًا.
2. ادمج (squash)، وسجّل الـSHA.
3. تحقق من النشر، **كله**:
   - Render: آخر نشر لخدمة `sabq.org` (`srv-dbcgjcom7kps739tsa7g`) بحالة `live` وبالـSHA نفسه
   - `https://api.sabq.org/api/version` يعيد الـSHA نفسه
   - `https://api.sabq.org/health` سليم
   - Cloudflare Pages (مشروع `sabq-org`) آخر نشر من main ناجح إن مسّ الواجهة
   - افحص المسار المتأثر نفسه (الرابط أو الـendpoint)، لا الصفحة الرئيسية فقط
4. رد قصير: تم، والـSHA، وما فحصته، وما لم يُفحص (مثل: يحتاج تجربة على جهازك).

## مثال جيد 1
«اعتمد» على إخفاء بريد الكتّاب ← PR #1965 بتعديل الاستعلامين واختبار. ثم «ادمج» ← دمج، وRender live بالـSHA `dbb6ae0`، و`/api/version` مطابق، وفحص 5 روابط بلا بريد، وSmoke أخضر.

## مثال جيد 2
ميزة تحتاج عمودًا جديدًا ← ملف `migrations/2026xxxx_*.sql` مع الصلاحيات، ورسالة: «نفّذ الملف أولًا ثم قل تم تنفيذ». الدمج بعد «تم تنفيذ» و«ادمج».

## مثال سيئ (ولماذا)
«اعتمد» ← PR ثم دمج مباشرة، والرد: «تم النشر، الخادم يعيد 200».
**لماذا سيئ:** «اعتمد» لا تعني الدمج، و200 من الصحة لا يثبت أن الكود الجديد هو الذي يعمل ولا أن المسار المتأثر سليم.

## ممنوع
- الدمج بلا «ادمج» لهذا الـPR، أو تجاوز فحص أحمر، أو `--no-verify`، أو force-push على main.
- `./push-to-production.sh` أو `db:push` على الإنتاج.
- تغيير إعدادات Render أو Cloudflare ضمن هذه المهارة (لها طلب «نفّذ» مستقل).
