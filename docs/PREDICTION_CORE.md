## 1. ما هي المنصة ولماذا

قبلها كان لدينا **~15 محرك توقعات متناثرًا** (كأس العالم، روشن، الكؤوس، خليجي، آسيا، المسبح المعمّم، الهدافون، الأقسام...) لكل منها جداوله ومنطقه ولوحته، مع تداخلات خطرة (بطولة واحدة تُسوّى بمحركين بأرقام مختلفة) وخلط بين نقاط التنافس ومضاعف العضوية.

اليوم: **محرك واحد** يخدم كل البطولات بقواعد مختلفة لكل بطولة، **باستثناء وحيد**: مونديال 2026 بقي على محركه القديم حتى نهايته (قرار مالك 2026-07-17 — البطولة شارفت على الانتهاء ولا تُمس كودًا ولا بيانات).

**المبدأ الحاكم:** القواعد المتغيرة إعدادات مُرقّمة الإصدار في قاعدة البيانات، ومنطق التنفيذ استراتيجيات برمجية مختبرة مسجلة بالاسم. لا كود داخل JSON، ولا خدمة جديدة لبطولة جديدة — بطولة جديدة = صف Competition + ملفات Scoring Profiles.

## 2. كيف تعمل — دورة الحياة الكاملة

```
مصدر المباريات (saudiLeagueService / gulfCupService / asianCupService)
   │  كل دقيقة — predictionCoreJob (بقيادة isLeader)
   ▼
[1] fixtureAdapter: مزامنة
      مباراة جديدة داخل أفق 14 يومًا  → مسابقة open (external_ref = fixtureId)
      تأجيل/تقديم قبل البداية         → تحديث locks_at
      صافرة نهاية FT/AET/PEN + أهداف  → تثبيت النتيجة → status: ready
      CANC/ABD/WO/AWD                → void (قرار إداري ≠ نتيجة ملعب)
   ▼
[2] lockDueContests: open → locked عند ضربة البداية (وقت الخادم حصرًا)
   ▼
[3] settleReadyContests: لكل مسابقة ready —
      قفل استشاري (pg_advisory_xact_lock) لكل مسابقة + لكل بركة
      صف تسوية فريد (contest, result_version, strategy_version) يُستأنف بعد فشل
      تشغيل الاستراتيجية (دالة نقية حتمية) على التوقعات النشطة
      كتابة Settlement + Ledger + Carry + Outbox + الحالة في Transaction واحدة
   ▼
[4] deliverPendingAwards: تسليم Outbox للمحفظة عبر awardPoints حصرًا
      source = prediction:<ledgerId> → dedup مدى الحياة يمنع الازدواج
      backoff أُسّي حتى 8 محاولات ثم failed (dead-letter)
   ▼
[5] settleGulfDuels: تسوية تحديات المجلس (خليجي) من حالة المباريات النهائية
```

**فصل النقاط (أهم مبدأ منتج):** سجل `prediction_points_ledger` يحمل نقاط البطولة **الأساسية** (تغذي الترتيب)، ومضاعف العضوية (1.0×–1.5× حسب طبقة الولاء) يُطبَّق **في Outbox فقط** على قيمة المحفظة. اللوحات لا تعرف المضاعف، والمحفظة تعرفه بسجل snapshot.

**التصحيح بعد تعديل نتيجة رسمية:** لا تعديل أرقام أبدًا — `reverseAndReopen(contestId, newResult)` ينشئ تسوية عكسية بقيود سالبة + يرفع نسخة النتيجة + يعيد المسابقة ready، فيعيد العامل تسويتها بالنتيجة الصحيحة. (استرداد المحفظة قرار منتج معلق — القسم 8.)

### 2.1 الاستراتيجيات المسجلة (`server/services/predictions/registry.ts`)

| المفتاح | المنطق | تستخدمه |
|---|---|---|
| `tiered_pool` | بركة (1000 افتراضيًا) بطبقات حصرية 50/30/20 (دقيق/فارق موقّع/اتجاه) + ترحيل Jackpot — **منطق خليجي 27 الأصلي مستوردًا من `gulfCupPredictionScoring.ts` لا منسوخًا** | روشن، السوبر، خليجي 27 |
| `shared_pool` | بركة تُقسم بالتساوي على المصيبين (معيار الإصابة exact/outcome معامل) | كأس الملك (500 دقيق) |
| `fixed_points` | نقاط ثابتة 3/1/0 | متاح (النظام الكلاسيكي سابقًا) |
| `skill_weighted` | طبقات × جرأة × سلسلة (مضاعفات ×100 أعداد صحيحة) | كأس آسيا 2027 |
| `player_pool` | بركة اختيار لاعب (هداف 300 / أول هداف 200) | خليجي (واجهته لاحقة) |
| `long_term_pool` | بطل/هداف بتوزيع متساوٍ أو موزون بالتبكير | كل البطولات (واجهته لاحقة) |

خصائص مضمونة بالاختبارات (`tests/unit/predictionStrategies.test.ts` + `predictionFixtureSync.test.ts`): حفظ البركة (`awarded + carried + remainder === available`)، الحتمية، حماية النتيجة المقلوبة، والقص الآمن للمضاعفات. كل الحسابات أعداد صحيحة — لا floating point.

### 2.2 الجداول (في `shared/schema.ts` — إنشاؤها الإنتاجي عبر سكربت DDL لا db:push)

`prediction_competitions` (البطولات) · `prediction_scoring_profiles` (قواعد مُرقّمة الإصدار — لا يُعدَّل ملف مستخدم، التغيير إصدار جديد) · `prediction_contests` (مسابقة قابلة للإغلاق والتسوية، قيد فريد على external_ref) · `prediction_entries` (توقع نشط واحد لكل مستخدم/مسابقة، يثبّت إصدار القاعدة وقت الإرسال) · `prediction_settlements` (سجل التشغيل + input_hash) · `prediction_points_ledger` (Append-only، التصحيح بقيد عكسي) · `prediction_pool_state` (رصيد الترحيل) · `prediction_award_outbox` (جسر المحفظة، قيد فريد على ledger_id).

### 2.3 المسارات

- **ويب** `/api/predictions/*` (جلسة Passport) — `server/routes/predictionsCore.ts`
- **موبايل** `/api/v1/predictions/*` (Bearer — جلسات `app_member_sessions` القائمة عبر `memberSessionService`) — `server/routes/predictionsMobile.ts`
- نفس الخدمة (`predictionCoreService`) ونفس معاني الحقول في المسارين. رموز أخطاء موحدة (`PREDICTION_LOCKED`، `CONTEST_NOT_OPEN`...) في `shared/predictions.ts`.

### 2.4 الواجهات الأربع (التصميم المعتمد 2026-07-17)

| المنصة | الموضع | ملاحظات |
|---|---|---|
| ويب | `sabq.org/predictions` (+ `?competition=<slug>` روابط عميقة) | `client/src/pages/PredictionCenter.tsx` + `components/predictions/` — المسارات القديمة الخمس تحوّل إليها |
| iOS | تطبيق الرياضة SabqSports ← قائمة الحساب ← «توقّعات VARA» | ثلاثية Swift في `sports app ios` — هوية SpTheme |
| Android | تطبيق سبق الأصيل ← الإعدادات ← «توقّعات البطولات» | `android-native/…/feature/predictions/` — هوية SabqTheme |

**قاعدة الهوية (توجيه مالك مهم):** مركز التوقعات يلبس ثيم التطبيق المستضيف — لا ألوان مستقلة ولا ثيم من الخادم.

## 5. دليل التشغيل (Runbook)

كل الأوامر من جذر المستودع على أحدث main، عبر `railway` CLI مرتبطًا بمشروع sabq.org / production / خدمة sabq.org (`railway link -p 49260270-79b7-40af-9e91-2599a6161f46 -e production -s sabq.org`).

> ⚠️ إن كان في مجلدك `.env.local` يحوي `NEON_DATABASE_URL` محليًا، أزحه قبل `railway run` — الكود يفضّل `NEON_DATABASE_URL` على `DATABASE_URL` وقد يصيب قاعدة التطوير بدل الإنتاج.

| العملية | الأمر |
|---|---|
| عرض البطولات وحالاتها | `railway run npx tsx scripts/set-prediction-competition-status.ts` |
| تفعيل/إيقاف بطولة | `railway run npx tsx scripts/set-prediction-competition-status.ts <slug> <active\|paused\|draft\|completed>` |
| إنشاء الجداول (idempotent) | `railway run npx tsx scripts/apply-prediction-core-tables.ts --apply` |
| الزرع (idempotent) | `railway run npx tsx scripts/seed-prediction-core.ts` |
| مسح تجارب (معاينة/تنفيذ) | `railway run npx tsx scripts/wipe-prediction-experiments.ts [--execute]` |
| **إيقاف طارئ شامل** | `railway variables --set "PREDICTION_CORE_ENABLED=false"` — كل شيء يصمت فورًا والبيانات كلها تبقى |
| تصحيح نتيجة مسوّاة | برمجيًا عبر `reverseAndReopen` في `settlementService` (لوحة إدارة لاحقًا) |
| إعادة رسالة محفظة فاشلة | `retryFailedAward(outboxId)` في `outboxService` |
| فحص الصحة | `curl api.sabq.org/api/predictions/competitions` + ‏`railway logs \| grep "Prediction Core"` |

**بطولة جديدة** = إدراج Competition + Profiles (انظر `seed-prediction-core.ts` كنموذج) + مصدر مباريات في `FIXTURE_SOURCES` داخل `fixtureAdapter.ts` إن كانت من مصدر جديد — لا محركات ولا جداول جديدة.

**التراجع ليس حذفًا:** إيقاف العلم أو البطولة يحفظ كل التوقعات والقيود؛ النقاط الخاطئة تُعالج بقيود عكسية لا بتعديل أرقام.

## 9. Gotchas — اقرأها قبل أن تلمس

- **المونديال مقدس حتى نهايته**: `wc*` خدمات/مهام/مسارات/جداول/شاشات — لا تُلمس، ولا يظهر في المنصة المركزية ولا في سكربت المسح.
- `gulfCupPredictionScoring.ts` ليس بقايا — هو **قلب** `tiered_pool`. توثيقه الداخلي فيه مثال «outcome» خاطئ (2-1 ضد 1-0 فارقٌ لا اتجاه) — الكود هو الصحيح.
- `NEON_DATABASE_URL` يغلب `DATABASE_URL` في `server/db.ts` — احذر `.env.local` عند `railway run` (انظر §5).
- سكربتات `scripts/` تستخدم `const { db } = await import("../server/db")` **بعد** dotenv — رفع استيرادات ESM يكسر النمط الآخر.
- تثبيت النتيجة مرة واحدة: المحوّل لا يلمس مسابقة `ready`/`settled` — التصحيح حصريًا عبر `reverseAndReopen`.
- `predictionsEnabled` في `/api/rsl/hero` يقرأ الآن `PREDICTION_CORE_ENABLED` (بقي لثبات العقد).
- اختبار محلي سريع: `scripts/preview-prediction-demo.ts` (غير مثبّت في git) يزرع مباريات تجريبية بكل الحالات.
