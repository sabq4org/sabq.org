# متطلبات حاوية شركة الإعلانات — GTM-T5PW84LM

مرجع: Issue #1646، تدقيق 2026-09-12. أكد مالك سبق أن هذه الحاوية تخص شركة الإعلانات. لم يُنشر أو يُعدّل شيء فيها خلال إصلاح المشروع. هذه قائمة تسليم فنية، وليست رسالة أُرسلت للشركة.

1. تصدير نسخة الحاوية المنشورة الحالية وفرق مساحة العمل غير المنشور، مع تاريخ النشر. قيمة resource.version=69 في الملف العام ليست إثباتًا لرقم إصدار واجهة GTM.
2. الحفاظ على تعطيل Google tag/GA4 pageview داخل حاوية الإعلانات ما دام المشروع يملك القياس المباشر. راجع `virtual_pageview` وhistoryChange؛ لا تفعّل الوسوم القديمة كتعديل إعلاني جانبي.
3. تحديد حساب Google CMP/Funding Choices الذي يحقن الرسالة في sabq.org، والرسالة المنشورة والمناطق والإصدارات الفعلية. حساب Ad Manager الظاهر لسبق لا يثبت ملكية CMP الذي يأتي من الحاوية.
4. تفعيل الربط المناسب مع Consent Mode من CMP المالك، بما يشمل analytics_storage وad_storage وad_user_data وad_personalization وفق الاختيارات الحقيقية. لا طبقتان ترسلان consent update مستقلين، ولا استنتاج موافقة من وجود FCCDCF/FCNEC.
5. مراجعة consent checks للوسوم المخصصة، خصوصًا Permutive وNovatiq وبقية الموردين. وسوم Custom HTML لا تكتسب تلقائيًا ضمانات وسوم Google.
6. تنقية page URL/referrer/search term في مصادر متغيرات الحاوية، وعدم تشغيل التتبع على صفحات الحساب/المصادقة أو تمرير رموز التحقق والاستعادة. يلزم اختبار انتقال SPA من صفحة عامة سبق تحميل وسومها إلى صفحة حساسة، وليس الفتح المباشر فقط.
7. الكود يكتب `signal.User.EmailHash` بينما المورد المنشور يقرأ `signal.User.Email`. لا تُصحَّح المطابقة بتمرير بريد صريح. راجع الحاجة والرضا وآلية التجزئة والـidentify قبل توصيل أي هوية؛ الإرسال الفعلي للبريد لم يثبت في التدقيق.
8. اختبار صفحة جديدة بلا كوكيز بالسعودية والمنطقة الأوروبية: رفض/قبول/سحب، وفشل CMP، والانتقال الداخلي. وثّق الوسوم التي أطلقت وسبب الموافقة لكل منها، والمعلمات المنقّحة، ثم اطلب اعتماد نشر النسخة المحددة.

لا تُغيّر GTM-KRVQHS9 ولا تستبدل معرّف الشركة به؛ وجوده في حساب سبق لا يجعله الحاوية المستخدمة.
