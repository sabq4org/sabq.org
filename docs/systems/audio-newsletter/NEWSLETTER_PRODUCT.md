# سبق في ٣ دقائق — عقد المنتج والإطلاق

> 2026-09-24 — تتبع التنفيذ: [Issue #1723](https://github.com/sabq4org/sabq.org/issues/1723)

## الوعد للقارئ

نشرة عربية مختصرة مع روابط الأخبار الأصلية، يختار القارئ إصدارًا يوميًا أو أسبوعيًا. تبدأ النسخة الأولى بخمس قصص. التأكيد بالبريد يسبق تفعيل الاشتراك. لا يوعد بموعد إرسال ثابت قبل اجتياز اختبار التسليم وإطلاق التشغيل فعليًا.

تظهر الدعوة للاشتراك داخل الرئيسية وبعد الخبر وفي التنقل والتذييل، دون نافذة منبثقة. تعرض صفحة `/newsletter` القيمة ونموذجًا توضيحيًا وبريدًا وتفضيل وتيرة الإرسال وموافقة واضحة. الاهتمامات اختيارية ولا تعني ضمان تخصيص كل رسالة في المرحلة الأولى.

## فصل المسؤوليات

- سبق: الاشتراك المؤكد وتفضيلاته، اختيار المصادر المنشورة، إعداد المسودة، التعديل والمراجعة البشرية، تصدير النسخة المعتمدة.
- MailerLite: إعداد الحملة وجمهورها ومعاينة البريد واختبار التسليم والإرسال وإلغاء الاشتراك وتقارير المزود.
- MailerSend/SendGrid: رسائل الخدمة مثل تأكيد ملكية البريد. لا تستخدمهما كمسار احتياطي لإرسال الحملة التسويقية الجديدة.
- الذكاء الاصطناعي: يساعد على تلخيص النص المنشور. لا يتلقى قائمة المشتركين أو عناوينهم، ولا ينشئ حقائق بلا مصدر، ولا يعتمد أو يرسل الرسالة.

## رحلة الاشتراك

1. يرسل النموذج البريد والوتيرة `daily | weekly` والموافقة الصريحة.
2. الاستجابة لا تكشف وجود البريد أو حالة منعه، ولا تعني أن الاشتراك نشط.
3. تحفظ بصمة رمز عشوائي محدود الصلاحية؛ الرابط يحمل الرمز في fragment.
4. فتح الرابط وحده لا يفعّل الاشتراك؛ زر التأكيد يرسل POST.
5. بعد التأكيد تتم مزامنة اشتراك مؤهل مع MailerLite. تعثر المزود يظل حالة قابلة للملاحظة وإعادة المحاولة، وليس نجاح تسليم.
6. تبقى حالات الارتداد والشكاوى والمنع محفوظة؛ لا يعاد تفعيل البريد لمجرد إرسال فورم عام.

التخزين يستعمل أعمدة الاشتراك الموجودة؛ لا يحتاج هذا التنفيذ إلى دفع schema على الإنتاج. لا تستنتج صحة الاشتراكات التاريخية من `verifiedAt` القديم، إذ كان المسار السابق يملؤه دون تأكيد فعلي. تشترط مزامنة مجموعات الوتيرة الجديدة marker `newsletterConsentVersion: 1` و`confirmedAt`. تبقى معالجة مسار الموبايل v1 القديم في [Issue #1724](https://github.com/sabq4org/sabq.org/issues/1724)؛ لا يشمل هذا التغيير ترحيل موافقاته أو واجهاته.

تنتظر واجهة WebMCP تأكيد البريد أيضًا. تعيد عمليات التفضيل والإلغاء `mailerliteSynced`، وتعرض الواجهة التعثر بوضوح. تحفظ حالة المزامنة للمراجعة وإعادة المحاولة الإدارية، وإعادة محاولة الإلغاء لا تعيد تفعيل الاشتراك.

## دورة التحرير

`مصادر منشورة ← مسودة ← مراجعة وتعديل ← اعتماد نسخة محددة ← تصدير HTML ← اختبار MailerLite ← إرسال معتمد`

التعديل يبطل الاعتماد السابق. النسخة المصدرة يجب أن تطابق بصمة الاعتماد؛ المعاينة ليست إرسالًا. يُحفظ إسناد القصص والمحرر ووقت الاعتماد. إذا سحب خبر أو تغير بعد إعداد المسودة، يعاد التحقق قبل تجهيز الحملة.

الجداول التاريخية `audio_newsletters` و`audio_newsletter_articles` مستعملة أصلًا للنشرة البريدية بعد إلغاء الصوت؛ لا يعيد هذا المنتج تشغيل TTS أو RSS الصوتي. لا تحذف سجلات التسليم القديمة.

## القياس

- ظهور النموذج وطلبات الاشتراك حسب الموضع والوتيرة، دون بريد أو رمز تحقق في التحليلات.
- التحويل من طلب الاشتراك إلى التأكيد الفعلي، وإخفاق مزامنة المزود.
- زيارات المقالات المنسوبة إلى `utm_source=mailerlite` و`utm_medium=email` بحسب الحملة.
- الاحتفاظ بالمشتركين، النقرات، إلغاء الاشتراك والارتداد. فتح البريد مؤشر مساعد وليس وحده مقياس نجاح بسبب التحميل الآلي للصور.
- اختبار كل موضع منفصلًا قبل إضافة إصدارات أو رسائل أكثر.

هذه قائمة القياس المطلوبة للإطلاق؛ لا تعني أن لوحة التحليلات القديمة تستقبل أحداث MailerLite الجديدة تلقائيًا.

## قبول الإطلاق التشغيلي

- [ ] نشر Backend ثم واجهات SPA/SSR، وإثبات نسخة النشر.
- [ ] اختبار البريد الجديد: pending، وصول التأكيد إلى صندوق تحت سيطرة الفريق، ثم POST واحد ناجح وتكراره الآمن.
- [ ] اختبار expired/invalid، رفض المنع/الارتداد، وإخفاق المزود دون ادعاء نجاح.
- [ ] اختبار daily/weekly في MailerLite والجمهور المطابق؛ لا استيراد قائمة قديمة غير مثبتة الموافقة.
- [ ] فحص قالب عربي RTL في Gmail وApple Mail وOutlook والجوال، والروابط والتذييل وعنوان الشركة الحقيقي ورابط إلغاء الاشتراك.
- [ ] تعيين محرر مسؤول عن مراجعة المصادر واعتماد كل إصدار.
- [ ] معاينة حملة تجريبية محدودة وعنوان From/Reply-To معتمدين، ثم إثبات وصولها وإلغاء الاشتراك وتوقف الرسائل اللاحقة.
- [ ] إبقاء المسار القديم والمهام المتراكمة غير قابلة للإرسال، ومراجعة إعدادات التشغيل قبل أي تفعيل.

لا يكفي نجاح build أو قبول المزود للطلب لإعلان وصول الرسالة. لا توجد هجرة بيانات أو إرسال للجمهور ضمن اختبارات الكود.

## مراحل لاحقة

بعد قياس النسخة الأولى: الاهتمامات والتقسيم، رسالة أسبوعية متخصصة، نشرات المناطق، ثم الرعاية مع وسم واضح. لا تنشأ هذه الإصدارات أو رسائل عاجلة تلقائيًا من هذا الاعتماد.
