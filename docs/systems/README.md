# كتالوج أنظمة سبق (Systems Catalog)

هذا المجلد هو **مصدر الحقيقة** لخريطة الأنظمة داخل المشروع:
الولاء، التوقعات، التحرير، iFox، المقترب، … إلخ.

الهدف ثلاثي:

1. **تنظيم التوثيق** — كل نظام له ملف `SYSTEM.md` واحد يُحدَّث مع الكود.
2. **حوكمة الـ Agents** — لا يبدأ أي Agent تعديلاً على نظام إلا بعد قراءة ملفه.
3. **لوحة الكتالوج** — `/dashboard/systems-catalog` تعرض العدد، الملفات، وحالة استهلاك الذكاء الاصطناعي (عند التوفر).

---

## الملفات

| ملف | الدور |
|-----|--------|
| [`registry.json`](./registry.json) | سجل آلي قابل للقراءة من السكربتات والـ API |
| `<id>/SYSTEM.md` | وثيقة النظام الإلزامية للـ Agents والبشر |
| [`GOVERNANCE.md`](./GOVERNANCE.md) | قواعد التحديث والتنظيم |
| هذا الملف | نقطة الدخول |

---

## قاعدة الـ Agent (إلزامية)

قبل أي تعديل يمس مسارات نظام معيّن:

1. افتح [`registry.json`](./registry.json) وحدّد `id` النظام من `pathGlobs` / `docPath`.
2. اقرأ `docs/systems/<id>/SYSTEM.md` كاملاً.
3. اذكر في أول ردّ عملي: «قرأت `docs/systems/<id>/SYSTEM.md`».
4. لا توسّع النطاق خارج حدود النظام إلا بموافقة صريحة أو Issue منفصل.

التفاصيل في [`.cursor/rules/systems-docs-gate.mdc`](../../.cursor/rules/systems-docs-gate.mdc) و[`AGENTS.md`](../../AGENTS.md).

---

## إضافة نظام جديد

1. أضف مدخلاً في `registry.json` (لا تحذف مدخلاً قديماً — عطّله بـ `"status": "retired"`).
2. أنشئ `docs/systems/<id>/SYSTEM.md` من القالب في `GOVERNANCE.md`.
3. حدّث `pathGlobs` بدقة حتى يحسب السكربت الملفات صح.
4. اربط `aiFeatureKeys` إن كان النظام يمر عبر AI Gateway.
5. شغّل: `node scripts/systems-inventory.mjs`

---

## أوامر سريعة

```bash
# جرد محلي: عدد الملفات + مسارات التوثيق
node scripts/systems-inventory.mjs

# نفس البيانات عبر API (لوحة التحكم، صلاحية system.manage_settings)
GET /api/admin/systems-catalog
```
