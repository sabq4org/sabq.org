# حوكمة توثيق الأنظمة

## مبدأ واحد

> **الكود بدون `SYSTEM.md` محدّث = دين تقني.**  
> أي PR يغيّر سلوك نظام يجب أن يلمس ملف النظام أو يذكر صراحة لماذا لا يلزم التحديث.

## أين تضع ماذا؟

| نوع المحتوى | المكان |
|-------------|--------|
| خريطة النظام، حدود المسؤولية، نقاط الدخول، مخاطر | `docs/systems/<id>/SYSTEM.md` |
| سجل آلي (id، globs، روابط) | `docs/systems/registry.json` |
| تقرير لمرة واحدة / تحقيق حادثة | `docs/reports/` أو `docs/handoff/` |
| إعداد بيئة / أسرار / نشر | `docs/setup/` أو `docs/DEPLOYMENT_STATUS.md` |
| قواعد Agents عامة | `AGENTS.md` + `.cursor/rules/` |
| مرجع معماري عابر للأنظمة | `docs/architecture/` |

**لا** تضف وثيقة نظام جديدة في جذر `docs/` إن كان لها نظام في السجل — حدّث `SYSTEM.md` واربط الوثيقة القديمة منه.

## قالب SYSTEM.md

```markdown
# <اسم النظام بالعربية> (`<id>`)

> آخر مراجعة: YYYY-MM-DD | المالك: فريق …

## الغرض
جملة أو اثنتان: ماذا يفعل النظام ولمن.

## الحدود (In / Out of scope)
- داخل النطاق: …
- خارج النطاق: … (أنظمة مجاورة بروابط)

## نقاط الدخول
| الطبقة | المسار |
|--------|--------|
| Backend | `server/services/…`, `server/routes/…` |
| Web | `client/src/…` |
| iOS | `ios/…` |
| Android | `android-native/…` |
| Schema | جداول في `shared/schema.ts` |

## التوثيق المرتبط
- روابط لوثائق موجودة (لا تنسخ المحتوى)

## عقود مهمة / Gotchas
- ما يكسر الإنتاج إن نُسي

## صحة وتشغيل
- كيف تعرف أنه يعمل؟ (endpoint صحة، كرون، لوحة)
- استهلاك AI: مفاتيح `featureKey` إن وُجدت

## عند التعديل
Checklist قصيرة للـ Agent قبل الإغلاق
```

## قواعد التحديث

1. **Additive على السجل**: أضف حقولاً، لا تحذف `id` مستخدماً.
2. **تاريخ المراجعة**: حدّث `lastReviewed` في `registry.json` و«آخر مراجعة» في `SYSTEM.md`.
3. **Globs دقيقة**: تجنّب `**/*` العريض الذي يبتلع نصف الريبو.
4. **لا secrets** في أي ملف تحت `docs/systems/`.
5. **Agent gate**: راجع `.cursor/rules/systems-docs-gate.mdc`.

## تعدد الـ Agents

عند تشغيل أكثر من Agent بالتوازي:

- خصّص لكل Agent **نظاماً واحداً** (`id` من السجل) قدر الإمكان.
- إن تقاطع نظامان (مثلاً توقعات + ولاء للنقاط)، افتح Umbrella Issue وحدّد ترتيب الدمج.
- Agent ثانٍ لا يعدّل `registry.json` بينما الأول يعدّل نفس المفاتيح — اجعل تغييرات السجل في PR منفصل صغير.
