# ملاحظات تشغيل الإنتاج: الكاش والإقلاع

## Redis في الإنتاج

- عند تشغيل أكثر من نسخة Backend، يجب ضبط `REDIS_URL`.
- بدون Redis تبقى الجلسات وبعض جسور البث الحي داخل ذاكرة النسخة الواحدة، وهذا مناسب للتطوير فقط.
- وجود Redis يقلل ضغط قاعدة البيانات للجلسات ويحافظ على تناسق إشعارات SSE بين النسخ.

## أعمال الإقلاع

- تجنب نقل أعمال صيانة ثقيلة إلى مسار بدء الخادم مباشرة.
- أي فهرسة، تنظيف، أو إعادة حساب كبيرة يجب أن تعمل كـ job منفصل أو maintenance run.
- قبل إضافة أي عمل عند الإقلاع، قس أثره على زمن بدء الحاوية وعلى قاعدة البيانات في Railway/Replit.

## قاعدة الرجوع

- أي تحسين تشغيل يجب أن يكون قابلاً للتعطيل بمتغير بيئة أو عكسه في PR مستقل.
- لا تغييرات schema في هذا المسار إلا بإضافة حقول فقط وبحسب Workflow C في `AGENTS.md`.
