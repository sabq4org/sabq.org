# إصلاح انزياح إعلان DMS المطفأ — 7 سبتمبر 2026

مرتبط بـ #1533. الحالة: إصلاح محلي مفحوص؛ لا ادعاء بتحسن قياسات الإنتاج قبل النشر.

## الدليل

[PageSpeed لصفحة nonl2o0](https://pagespeed.web.dev/analysis/https-sabq-org-article-nonl2o0/bqa540jzun?form_factor=mobile) أعاد CLS=0.289 للجوال، مع حركتين متعاكستين لـ main.container (0.145 تقريباً لكل واحدة). بيانات المستخدمين خلال28 يوماً: CLS=0.33 وLCP=5.4s. الاختبار المختبري: LCP=8.8s وPerformance=35.

قراءة سكربت GTM العام `GTM-T5PW84LM` أثبتت أنه ينشئ `#Leaderboard` خارج React ويحقن قاعدة `display:block!important`، و`min-height:100px` ومارجن رأسي 32px. `DmsLeaderboardAd` يحذف الحاوية كل ثانية عند إطفاء الإعداد. لذلك يمكن أن يظهر فراغ132px ثم يختفي، حتى والإعداد مطفأ.

## التغيير

الحالة المحسومة من `useDmsTopAdsEnabled` تنعكس قبل الرسم على جذر المستند. عندما تكون مطفأة، قاعدة CSS أعلى أولوية تخفي حاويات Leaderboard حتى التي ينشئها GTM. تبقى آخر حالة معلومة أثناء الانتقال بين الصفحات. لا يشمل الإخفاء MPU، ويبقى سلوك التفعيل عند فشل جلب الإعداد كما هو.

## التحقق

اختبار متصفح محلي يستخدم ملف CSS الفعلي ويحاكي قاعدة GTM التي تُضاف بعده:

| السيناريو | تغيّر موضع main | النتيجة |
|---|---:|---|
| جوال412px — حقن الإعلان المطفأ | 0px | مخفي فوراً |
| جوال412px — حذف الإعلان المطفأ | 0px | لا حركة |
| سطح مكتب1280px — حقن الإعلان المطفأ | 0px | مخفي فوراً |
| تفعيل الإعلان ثم حقنه | 132px | ظاهر؛ القاعدة لا تعطل الإعلانات المفعلة |

MPU ظل بارتفاع250px في جميع الحالات. تمت معاينة نتيجة الاختبار بصرياً. بناء الويب وفحص TypeScript وESLint نجحت محلياً. الاختبار المعزول يثبت سلوك القاعدة، وليس نتيجة CLS النهائية لصفحة الإنتاج.

بعد النشر يلزم PageSpeed جديد وفحص الإعدادين على صفحة خبر فعلية. سبب إضافي لم يُعالج هنا: صورة الخبر تبدأ بلا أبعاد، وتصل بيانات أبعادها من طلب جانبي؛ يلزم إصلاح مستقل يحفظ نسبة الصورة دون قصّ. انخفاض تقرير CWV يتطلب تراكم زيارات جديدة خلال نافذة القياس.
