# سجلّ إصلاحات: تسريع النتائج اللحظية وويدجت شاشة القفل

- **التاريخ:** 2026-06-27
- **النطاق:** تطبيق سبق iOS · تطبيق سبق الرياضي iOS · تطبيق آسيا iOS · خادم دفع Live Activity
- **المرجع التشخيصي:** [`تشخيص_تأخر_النتائج_والويدجت.md`](./تشخيص_تأخر_النتائج_والويدجت.md)
- **الهدف:** خفض زمن وصول الهدف لشاشة القفل من **دقائق** إلى **~3–5 ثوانٍ**، محكوماً بسرعة تغذية المزوّد لا بطبقات الكاش/الخنق.

> **ملاحظة نشر:** تعديلات الخادم تسري فور إعادة النشر (Railway). تعديلات `Info.plist` تتطلب **إعادة بناء تطبيقات iOS ونشرها** عبر App Store لتسري. لم يُشغَّل `npm run check` كاملاً (تُقتل ذاكرة الساندبوكس على 251 جدولاً) — يلزم تشغيله محلياً/في CI قبل الدمج.

## التفاصيل

### 1–2) إضافة علم التحديثات المتكررة (iOS)

كان `NSSupportsLiveActivitiesFrequentUpdates` موجوداً في تطبيق سبق الرئيسي فقط ومفقوداً في سبق الرياضي وآسيا، فيفرض iOS ميزانية خنق صارمة → تأخير غير منتظم حتى 4 دقائق.

```xml
<key>NSSupportsLiveActivities</key>
<true/>
<key>NSSupportsLiveActivitiesFrequentUpdates</key>   <!-- مُضاف -->
<true/>
```

الملفات: `sports app ios/SabqSports/Info.plist` · `asian-cup app ios/AsianCup/Info.plist`.

### 3) أولوية APNs قابلة للضبط — `apnsService.ts`

أُضيف حقل اختياري للواجهة `LiveActivityUpdateOptions`، واستُخدم في ترويسة الدفع بدل القيمة الثابتة:

```ts
// واجهة الخيارات
priority?: "5" | "10";   // "10" فوري (افتراضي) · "5" موفّر للطاقة/الميزانية

// ترويسة liveactivity
"apns-priority": options.priority || "10",   // كانت: "10" ثابتة
```

### 4) تقسيم الأولوية حسب تغيّر النتيجة — `liveActivityService.ts`

خريطة في الذاكرة (القائد فقط) تتعقّب آخر نتيجة لكل مباراة؛ تغيّر النتيجة (هدف) أو النهاية يرفع الأولوية لـ`10`، والباقي `5`:

```ts
const lastScoreByFixture = new Map<number, string>();
// ...داخل الدورة:
const scoreKey = `${state.homeScore}-${state.awayScore}`;
const scoreChanged = lastScoreByFixture.get(fixtureId) !== scoreKey;
lastScoreByFixture.set(fixtureId, scoreKey);
const priority: "5" | "10" = finished || scoreChanged ? "10" : "5";
if (finished) lastScoreByFixture.delete(fixtureId);
// ...تُمرَّر priority إلى sendLiveActivityUpdate(...)
```

فقدان الخريطة عند إعادة التشغيل غير ضار (دفعة واحدة بأولوية `5`).

### 5) دورة عامل متكيّفة — `liveActivityWorker.ts`

استُبدل `setInterval(5s)` الثابت بـ`setTimeout` متسلسل: 2ث عند وجود مباريات بأنشطة فعّالة، 5ث عند الخمول.

```ts
const FAST_MS = 2_000;   // أثناء البث
const IDLE_MS = 5_000;   // خمول (لا توكنات)
// ...
if (summary.fixtures > 0) nextMs = FAST_MS;
if (!stopped) timer = setTimeout(() => void tick(), nextMs);
```

### 6) خفض كاش النتيجة الحية — `sportmonksService.ts`

```ts
// كان: withSWR("wc:livescores", 4000, 8000, fetchLiveScores)
return withSWR("wc:livescores", 1500, 3000, fetchLiveScores);
```

نداء `livescores/inplay` واحد يغطّي كل المباريات، فالضغط على المزوّد يبقى ~نداء/2ث.

## التحقق

- مراجعة الأنواع يدوياً: الحقل المُضاف اختياري ومتوافق؛ الأقواس متوازنة في الملفين المعدّلين بكثافة.
- **لم يكتمل** `npm run check` في الساندبوكس (قتل ذاكرة على حجم المخطط) — **مطلوب تشغيله محلياً/في CI**.
- اختبار ميداني مقترح: مباراة حية → رصد زمن وصول الهدف لشاشة القفل (هدف < 5ث)، ومراقبة سجلّ `[LiveActivity Worker]` وأي `push failures`.

## متبقٍّ (لم يُنفَّذ بعد)

تسريع **الويب**: توحيد استطلاع `/sports/live` (15ث ثابتة → 5–6ث متكيّفة) وخفض بائت الـCDN أثناء البث، و(استراتيجياً) قناة SSE/WebSocket بدل الاستطلاع متعدد الطبقات.
