- [ ] **0.4** التأكد أن لا أحد يشغّل `db:push` أو سكربتات ضد `DATABASE_URL` إنتاجي خارج `./push-to-production.sh`.

**معيار الاكتمال:** العلم مغلق، والـAPI يعيد 503 لمسارات المجالس/التوقعات الجديدة إن وُجدت.

## المرحلة 1 — مخطط قاعدة الإنتاج

الجداول/الأعمدة المتوقعة (من `shared/schema.ts` + فحص السكربت):

| عنصر | مطلوب |
|---|---|
| `gc_majalis` | نعم |
| `gc_majlis_members` | نعم |
| `gc_duels` | نعم |
| `gc_majlis_notification_deliveries` | نعم |
| `user_notification_prefs.gulf_cup_majlis` | نعم |

- [ ] **1.1** تشغيل `./push-to-production.sh '<PROD_DATABASE_URL>'` تفاعليًا (URL الفعّال: `NEON_DATABASE_URL` إن وُجد وإلا `DATABASE_URL`).
- [ ] **1.2** قراءة preflight السكربت: `gc_majalis` قبل/بعد، و`search_path` لا يخفي الجدول.
- [ ] **1.3** التحقق اليدوي بعد الدفع:

```sql
select to_regclass('public.gc_majalis'),
       to_regclass('public.gc_majlis_members'),
       to_regclass('public.gc_duels'),
       to_regclass('public.gc_majlis_notification_deliveries');

select column_name
from information_schema.columns
where table_name = 'user_notification_prefs'
  and column_name = 'gulf_cup_majlis';
```

- [ ] **1.4** فحص معرّفات المباريات: لا صفوف يتيمة في جداول مرتبطة بـ`fixture_id` تشير لمباريات غير موجودة في مصدر خليجي الحالي (السكربت يطبع تحذيرات — عالجها قبل الفتح).

**معيار الاكتمال:** الجداول الأربعة + العمود ظاهرة في `public`، ولا تحذيرات IDs حرجة.

**معيار الاكتمال:** رابط الدعوة يعمل على ويب + iOS مثبت؛ Android verified أو موثّق كـfallback scheme فقط لهذا الإطلاق.

## المرحلة 4 — Smoke tests (قبل فتح العلم)

نفّذ على **staging** إن وُجد، وإلا على إنتاج بعلم **مغلق** حيث أمكن، ثم افتح العلم واختبر فورًا على حسابات داخلية.

### 4أ — المسار الاجتماعي الأساسي

- [ ] **4.1** إنشاء مجلس (حد الاسم، رمز الدعوة يظهر).
- [ ] **4.2** انضمام بعضو ثانٍ عبر الرابط (موافقة صريحة — لا join تلقائي بمجرد الفتح).
- [ ] **4.3** قبل kickoff: العضو يرى «توقّع ✓» مبهمًا للآخرين، لا النتيجة.
- [ ] **4.4** بعد الإقفال/أثناء الجارية: تظهر توقعات الأعضاء في `matchday`.
- [ ] **4.5** بانر بطل اليوم يظهر بعد تسوية مباريات اليوم.

### 4ب — الطبقات العميقة

- [ ] **4.6** تبويب فانتازي المجلس يعرض أعضاء المجلس فقط.
- [ ] **4.7** تبويب البطل يعرض اختيارات الأعضاء (أو حالة سرّية قبل الكشف حسب القواعد).
- [ ] **4.8** إنشاء تحدي 1×1 → قبول → اقتطاع نقاط → تسوية/استرداد عند void.
- [ ] **4.9** مغادرة/حذف مجلس مع تحديات نشطة تُرفض كما هو متوقع.

### 4ج — الإشعارات

- [ ] **4.10** تفعيل تفضيل إشعارات المجلس + إذن النظام.
- [ ] **4.11** تذكير قبل الإقفال (نافذة ~ساعتين): يصل لمن لم يتوقع وفي مجلسه متوقعون.
- [ ] **4.12** بعد التسوية: إشعار تجاوز ترتيب إن انطبق.
- [ ] **4.13** عند انضمام عضو جديد: إشعار للمجلس (بدون إزعاج مفرط / dedupe يعمل).

### 4د — الختام والهوية

- [ ] **4.14** `GET .../harvest` يعيد بيانات منطقية (حتى لو البطولة لم تنتهِ — حالات فارغة gracefully).
- [ ] **4.15** بطاقة الدعوة قابلة للمشاركة (ويب Canvas / iOS ImageRenderer / Android).
- [ ] **4.16** Onboarding يظهر مرة واحدة لكل مستخدم×مجلس ثم لا يعود.
- [x] **4.17** تمييز نصي: صاحب المجلس ≠ وسام «عميد» (10 أعضاء) — أُصلح على الويب؛ iOS/Android كانا صحيحين.

### 4هـ — المنصات

- [ ] **4.18** ويب: `/gulf-cup/majlis` و`/gulf-cup/predictions?tab=majlis`
- [ ] **4.19** iOS GulfCup: قائمة → تفاصيل → دعوة → push routing
- [ ] **4.20** Android-native: نفس المسار + فتح رابط

**معيار الاكتمال:** لا فشل حرج في 4أ–4ج على حسابين حقيقيين على الأقل.

## ملخص أوامر مرجعية

```bash
# 1) مخطط الإنتاج (تفاعلي — لا تستخدم db:push المباشر على prod)
./push-to-production.sh '<PROD_DATABASE_URL>'

# 2) بعد النشر والعلم مغلق — تحقق تعطيل
curl -sS -o /dev/null -w '%{http_code}\n' https://api.sabq.org/api/gulf-cup/majlis/mine

# 3) بعد فتح العلم — تحقق دعوة عامة (رمز تجريبي)
curl -sS "https://api.sabq.org/api/gulf-cup/majlis/invite/XXXXXX" | head
```
