# إجراءات الإشراف البشري والتصعيد

**الإصدار:** 1.0 — 2026-08-18 · المبدأ الحاكم: **الفشل نحو الإنسان** —
أي غموض أو تعذّر تقني يهبط بالقرار إلى مراجعة بشرية، لا إلى نشر آلي.

## 1. بوابات النشر حسب السطح

| السطح | البوابة | من يقرر |
|---|---|---|
| المقالات التحريرية (يكتبها البشر بمساعدة الذكاء) | المحرر يقبل أو يرفض كل مقترح | المحرر ثم سير النشر المعتاد |
| iFox والمهام المجدولة | مسودة افتراضيًا؛ نشر آلي فقط بتفعيل صريح + بوابة جودة (عتبة 90) | محرر iFox المكلف / إعدادات اللوحة |
| تغطيات الرياضة اللحظية | بوابات ما بعد التوليد («لا رقم بلا مصدر»، قوائم حظر) + وسم | مالك النظام الرياضي |
| التعليقات | آمن ← نشر؛ مشتبه ← طابور بشري؛ مرفوض ← قناة اعتراض | المشرفون (`comments.moderate`) |
| الصور المولدة | المحرر يختار ويُدرج (بصلاحية توليد) + وسم إلزامي | المحرر |
| الصوت (الموجز الصوتي) | نص مبني في الخادم من محتوى منشور حصرًا | تلقائي محكوم |

## 2. مراجعة مسودات iFox

1. المسودات تظهر في قائمة المقالات بحالة «مسودة» بمؤلف «سبق AI».
2. المحرر المكلف يراجع (دقة، مصادر، أسلوب) ثم ينشر أو يحذف.
3. تفعيل النشر الآلي قرار إداري من لوحة iFox (مفتاح `autoPublishEnabled`)،
   ويظل مشروطًا باجتياز بوابة الجودة؛ `requireHumanReview` يعطّل النشر الآلي
   كليًا حتى مع تفعيله.
4. فشل فحص الجودة أو تعذّر قراءة الإعدادات ← مسودة تلقائيًا.

## 3. طابور مراجعة التعليقات

- «مشتبه» يدخل الطابور فورًا؛ يعرض للمشرف التصنيف والدرجة والسبب الآليين.
- المعلّق أكثر من 24 ساعة بدرجة ≥ 70 وبلا مخالفة جسيمة يُنشر آليًا —
  المشرفون ملزمون بتصفية الطابور يوميًا حتى لا يتحول التأخر إلى نشر صامت.
- قرارات المشرفين تُغذّي معايرة النموذج؛ تُراجع عيّنة منها ربع سنويًا
  للتحقق من الاتساق.

## 4. قناة الاعتراض (التظلم)

1. إشعار الرفض يصرّح أن القرار آلي ويعرض زر «طلب مراجعة بشرية».
2. الاعتراض (مرة واحدة لكل تعليق، لصاحبه فقط) يعيد التعليق لحالة «معلّق»
   موسومًا «اعتراض من صاحب التعليق».
3. **مدة الفصل المستهدفة: 3 أيام عمل.** قرار المشرف بعد الاعتراض نهائي.
4. مقياس شهري: عدد الاعتراضات ونسبة قلب القرار — مؤشر جودة للنموذج
  يراجعه مسؤول الذكاء الاصطناعي.

## 5. مفاتيح الإيقاف

| المستوى | الأداة | الصلاحية |
|---|---|---|
| ميزة واحدة | `is_enabled` في لوحة مركز الذكاء الاصطناعي (`/api/admin/ai-hub`) | `ai_hub.manage` |
| نموذج واحد | `is_active` للنموذج (يخرج من سلاسل البدائل) | `ai_hub.manage` |
| نشر iFox الآلي | `autoPublishEnabled` / `requireHumanReview` في لوحة iFox | إدارة iFox |
| مزود كامل | سحب مفتاح API من متغيرات البيئة (Railway) ثم إعادة نشر | العمليات |

> تنبيه معروف: عند تعذّر قراءة الإعدادات من قاعدة البيانات تعود الميزات
> لافتراضيات «مفعّل» (fail-open) — بند مفتوح في سجل المخاطر؛ إيقاف مزود
> نهائيًا يكون بسحب مفتاحه لا بالمفتاح الإداري وحده.

## 6. سلم التصعيد عند الحوادث

1. **إنذار آلي:** قاطع الدارة يعزل النموذج المتدهور ويحوّل لبديله؛ التدهور
   الحرج يصل رئيس التحرير برسالة واتساب فورية.
2. **خط أول:** مالك النظام يقيّم (سجلات `ai_usage_logs` + لوحة المركز)
   ويطفئ الميزة إن لزم.
3. **خط ثانٍ:** مسؤول الذكاء الاصطناعي يقرر التصعيد: إيقاف أوسع، بيان
   للقراء، أو تصحيح محتوى منشور.
4. **محتوى منشور خاطئ:** يُسحب أو يُصحّح فورًا بقرار تحريري، ويُقيّد
   الحادث في سجل المخاطر مع درس مستفاد.
5. مراجعة ما بعد الحادث خلال أسبوع لكل حادث من الدرجة الحرجة.

## 7. المراجعة الدورية

- شهريًا: مؤشرات الاعتراضات، نسب الرفض الآلي، فحوصات جودة iFox.
- ربع سنويًا: عينة معايرة الرقابة، وسلامة الوسوم على أسطح النشر.
- نصف سنويًا: مراجعة الحزمة كاملة (لجنة الحوكمة).
