# خطة تطوير رادار سبق — من «جامع أخبار» إلى «رادار لا يفوت حدثاً»

> **التاريخ:** 2026-07-17 · **الحالة:** خطة معتمدة للتنفيذ — مُوسَّعة (v2)
> **مبنية على:** تدقيق الكود (`server/services/radar/**`, `server/routes/radar.ts`, `server/jobs/radarJob.ts`, `shared/schema.ts`, `docs/RADAR_X_WATCHES.md`) + هدف المنتج: تغطية عالمية كثيفة + رصد فوري عبر X
> **المبدأ الحاكم:** كل التغييرات **additive** — لا حذف/تعديل لأي جدول أو عمود أو عقد قائم. كل قدرة جديدة خلف Feature Flag.

---

## الرؤية (North Star)

> **رادار سبق يرى الخبر قبل أن يصبح «خبر الجميع»** — من وكالات ووسائل أمريكية/عالمية + حسابات إخبارية على X — خلال دقائق، مجمّعاً كقصة واحدة بزخم وصلة سعودية قابلة للقياس، ثم يُنبّه التحرير إن كانت فجوة تغطية.

### معايير نجاح المنتج (قابلة للقياس)

| المعيار | الهدف | كيف نقيسه |
|---|---|---|
| **اتساع التغطية** | ≥ 95٪ من «أحداث اليوم الكبرى» في الوكالات/الصحف الأمريكية تظهر كقصة خلال 15 دقيقة من أول نشر عام | عيّنة أسبوعية يدوية + سجل `radar_stories.first_seen_at` vs وقت النشر الأصلي |
| **فورية X (Tier A)** | تغريدة من حساب أولوية تصل للرادار خلال **≤ 2 دقيقة** من النشر | فرق `tweet.created_at` و`radar_items.fetched_at` |
| **فورية RSS (Tier A)** | مادة وكالة/صحيفة أولى خلال **≤ 5 دقائق** من ظهورها في الخلاصة | نفس الفرق على `published_at` |
| **عدم التكرار البصري** | قصة واحدة عبر N مصادر — لا N بطاقات | `source_count` ≥ 2 للأحداث المتزامنة |
| **صلة الجمهور** | قصص «ضوضاء أجنبية ضيقة» لا تزاحم لوحة المحرر | `saudi_relevance` + فلترة العرض |
| **فجوات حقيقية فقط** | بطاقة فجوة = قصة ذات زخم وصلة بلا تغطية داخلية | معادلة المرحلة 3 |

**«لا يفوتنا شيء» عملياً = اتساع مصادر + فورية جلب + تجميع + تنبيه** — ليس عدد RSS وحدها.

## 0) التشخيص الذي تُبنى عليه الخطة

الرادار اليوم: جامع RSS/JSON + بحث وترندات X (حقيقية، ليست stub) + تحليل LLM لحظي + تحويل تحريري. ما ينقصه ليكون راداراً يغطي العالم ولا يفوّت:

| الفجوة في القدرة | الدليل من الكود |
|---|---|
| بذور المصادر ضيقة (UK/عالمي خفيف) — بلا شبكة أمريكية | `scripts/seed-radar-sources.ts` = 6 مصادر فقط (BBC/Guardian/Sky/الجزيرة…) |
| لا تجميع للقصة الواحدة عبر المصادر | dedup لكل `(sourceId, guid)` فقط — `schema.ts` |
| لا قياس سرعة انتشار (velocity) | أرقام تفاعل X تُلصق كنص في excerpt — `xFetcher.ts` |
| القيمة الإخبارية = حكم LLM وحده | `analyst.ts` — لا إشارة كمية |
| لا تتبع للترند عبر الزمن | التقييم لحظي لكل مادة مستقلة |
| الصلة المحلية «برومبتية» فقط | لا فلترة محسوبة |
| رصدات X بلا واجهة إدارة | `SmartRadar.tsx` تقبل `rss\|json` فقط |
| «فوري» غير مضمون لحسابات X | فترة افتراضية 5 دقائق؛ لا مسار stream؛ النبض كل دقيقة لكن الجلب حسب `fetchIntervalMinutes` |

### القاعدة الذهبية (مُحدَّثة)

```
شبكة تغطية كثيفة (مصادر + حسابات X)
        ↓
إشارات كمية (تجميع + زخم + صلة)
        ↓
منتج للمحرر (قصص + تنبيهات)
        ↓
فجوات تغطية حقيقية
```

ميزة «فجوات التغطية» لا تُصلَح بتجميل واجهتها — ولا باتساع مصادر وحدها دون تجميع. **المرحلة 0 تعطي العيون؛ المرحلة 1 تعطي الدماغ؛ المرحلة 2 الشاشة؛ المرحلة 3 القرار التحريري.**

## المرحلة 0 — شبكة التغطية (العيون)

> **الهدف:** لا حدث كبير في الإعلام الأمريكي/الوكالات العالمية يمر دون أن يدخل الرادار — مع رصد فوري لحسابات الأخبار على X.
> **التقدير:** 5–8 أيام · **المخاطرة:** منخفضة تقنياً / متوسطة تشغيلياً (حدود API وتكلفة)
> **يمكن بدؤها فوراً** بالتوازي مع تصميم المرحلة 1 — تعطي قيمة تحريرية من اليوم الأول.

### المهمة 0.1 — كتالوج مصادر أمريكية + وكالات (RSS/JSON)

**الفكرة:** حزم بذور إصدارِيّة (versioned seed packs) بدل قائمة قصيرة يدوية. كل حزمة = ملف بيانات + سكربت بذر آمن للإعادة.

**طبقات المصادر (Tiers):**

| الطبقة | الدور | فترة الجلب الافتراضية | أمثلة (غير حصرية) |
|---|---|---|---|
| **A — وكالات سلكية** | أول إشارة عالمية | 3–5 دقائق | AP, Reuters, AFP, UPI (حيث تتوفر خلاصة عامة/مرخّصة) |
| **A — وطني أمريكي أول** | الأجندة الأمريكية | 5 دقائق | NYT, Washington Post, WSJ, USA Today, LA Times, Chicago Tribune |
| **B — شبكات وتلفزيون** | كسر عاجل ومرئي | 5–10 دقائق | CNN, NBC, ABC, CBS, Fox News, NPR, Politico, The Hill, Axios |
| **B — أعمال/تقنية** | أسواق وتقنية تمس المنطقة | 10–15 دقيقة | Bloomberg (عام إن وُجد), CNBC, TechCrunch, Wired |
| **C — إقليمي أمريكي انتقائي** | أحداث محلية تتصعّد وطنياً | 20–30 دقيقة | حزمة صغيرة قابلة للتوسيع لاحقاً |
| **خلفية عالمية** | رصد مقارن (قائم + توسيع) | 10–15 دقيقة | BBC, Guardian, Sky, Al Jazeera EN, DW, France24… |
| **سعودي/خليجي (وزن أعلى)** | صلة مباشرة لجمهور سبق | 5–10 دقائق | واس، صحف محلية، وكالات خليجية — حزمة منفصلة |

**تنفيذ:**

```
scripts/seed-radar-sources.ts          ← يبقى خفيفاً / توافق خلفي
scripts/seed-packs/
  us-wires.json                        ← وكالات
  us-nationals.json                    ← صحف وطنية أمريكية
  us-broadcast.json                    ← شبكات
  global-background.json               ← عالمي خلفي
  saudi-gulf.json                      ← محلي/خليجي (وزن أعلى)
scripts/seed-radar-pack.ts             ← يقرأ حزمة + onConflictDoNothing على url
```

كل مدخل في JSON:

```json
{
  "name": "AP — Top News",
  "url": "https://…",
  "type": "rss",
  "language": "en",
  "categorySlug": "world",
  "tier": "A",
  "region": "us",
  "fetchIntervalMinutes": 5,
  "weight": 1.2,
  "notes": "تحقق دوري من صلاحية الخلاصة"
}
```

**أعمدة additive اختيارية على `radar_sources` (إن لزم للفرز التشغيلي):**

```sql
ALTER TABLE radar_sources ADD COLUMN tier text;           -- A | B | C
ALTER TABLE radar_sources ADD COLUMN region text;         -- us | gulf | global | …
ALTER TABLE radar_sources ADD COLUMN weight real DEFAULT 1;
ALTER TABLE radar_sources ADD COLUMN pack_id text;        -- اسم الحزمة للتتبع
```

**قبول 0.1:** بعد بذر حزم A+B الأمريكية: ≥ 40 مصدراً نشطاً أمريكياً/وكالة؛ دورة واحدة تُدرج مواداً من ≥ 15 مصدراً مختلفاً خلال ساعة ذروة؛ تقرير صحة أسبوعي يُعلّم الخلاصات المكسورة (`last_error`).

**واقع الترخيص:** بعض الوكالات/الصحف لا توفّر RSS عاماً مجانياً. الخطة تفصل:
1. **ما يُبذر الآن** — خلاصات عامة موثّقة ومُختبَرة.
2. **ما يُفعَّل لاحقاً** — عبر اشتراك/ترخيص تحريري أو مسار X account كبديل فوري (المهمة 0.2).
3. سجل `docs/radar-source-licensing.md` (قصير) يذكر لكل مصدر: عام / يحتاج ترخيص / بديل X.

### المهمة 0.2 — شبكة حسابات X الإخبارية (فورية تشغيلية)

**الفكرة:** الحسابات الإخبارية المهمة = مصادر `type=x` / `xType=account` بفترة جلب قصيرة + `since_id` (القائم أصلاً) حتى لا نُعيد جلب القديم.

**قائمة أولوية (seed pack `x-news-accounts.json`) — أمثلة يجب تغطيتها:**

| الأولوية | أمثلة حسابات | فترة الجلب |
|---|---|---|
| **X-A (فوري)** | @AP, @Reuters, @AFP, @BBCBreaking, @CNN, @nytimes, @WSJ, @washingtonpost, @NBCNews, @ABC, @CBSNews, @FoxNews, @NPR, @politico, @axios | **1 دقيقة** |
| **X-B** | مراسلو وكالات بارزون، حسابات غرف أخبار خليجية/سعودية رسمية، @spa_en / حسابات واس، قنوات عربية كبرى | 2–3 دقائق |
| **X-C** | هاشتاقات/كلمات أحداث جارية (مونديال، أوبك، حج…) تُضاف مؤقتاً | 5 دقائق |
| **ترند** | رصدة `trend` السعودية (قائمة) | 10–15 دقيقة |

**SLA الفورية (تشغيلية قبل أي stream):**

| الطبقة | الآلية اليوم (بعد 0.2) | الهدف |
|---|---|---|
| X-A | `fetchIntervalMinutes=1` + نبض الـ job كل دقيقة + `since_id` | وصول ≤ 2 دقيقة |
| RSS-A | فترة 3–5 دقائق | وصول ≤ 5 دقائق |
| فشل مصدر | لا يوقف الدورة؛ يظهر في `last_error` + تنبيه صحة يومي للمحرر التقني | استعادة خلال الجلبة التالية |

**توجيه المزوّد (يتوافق مع `docs/RADAR_X_WATCHES.md`):**
- حسابات X-A/X-B → `x_provider=official` (أو `auto` الذي يفضّل الرسمي للحسابات).
- كلمات/هاشتاقات واسعة → `twitterapiio` لتقليل التكلفة.
- سقف حماية: `RADAR_X_MAX_ACTIVE_WATCHES` + رفض إضافة رصدة جديدة إن تجاوزنا الميزانية التقديرية.

**قبول 0.2:** بذر ≥ 25 حساب X-A/B؛ تغريدة اختبار من حساب مرصود تظهر في `radar_items` خلال دورتين؛ تكلفة يومية مُسجَّلة في لوغ الدورة لا تتجاوز سقف ENV تجريبي.

### المهمة 0.3 — مسار «أقرب لل瞬时» (Filtered Stream) — اختياري مرحلي

> الـ polling كل دقيقة يغطي SLA التشغيلي. الـ **stream** للمستقبل إن ارتفعت الميزانية/الخطة على X API.

- مزوّد رسمي: Filtered Stream / user timeline حيث تسمح الخطة.
- عملية منفصلة طويلة العمر (أو worker) تكتب في نفس `radar_items` بنفس عقد الـ guid.
- خلف `RADAR_X_STREAM_ENABLED=false` افتراضياً.
- عند تفعيله: حسابات X-A تنتقل من polling دقيقة → stream؛ الـ polling يبقى سقوطاً آمناً كل 5 دقائق.

**لا تُحجَز المرحلة 0 على الـ stream** — الـ polling الاحترافي يكفي لإطلاق الشبكة.

### المهمة 0.4 — صحة الشبكة ومؤشر «هل فاتنا شيء؟»

**لوحة صحة خفيفة (API + تبويب صغير لاحقاً في 2.x):**

- مصادر حمراء: `last_error` خلال 24س أو بلا مواد رغم كونها نشطة.
- **Miss probe أسبوعي (يدوي ثم نصف آلي):** قائمة 10 أحداث من AP/Reuters/NYT لليوم → هل لها `radar_story`؟ إن لا → فجوة شبكة (مصدر ميت / خلاصة ناقصة / حساب غير مرصود).
- مقياس تشغيلي: `coverage_freshness_p95` بالدقائق لكل tier.

**قبول 0.4:** تقرير أسبوعي واحد على الأقل يُنتَج من سكربت `scripts/radar-coverage-report.ts` (stdout + JSON اختياري).

### المهمة 0.5 — واجهة إدارة المصادر والرصدات (حد أدنى للتشغيل)

حتى لا تعتمد الشبكة على API فقط:

- تبويب مصادر: إضافة/تعطيل/تغيير الفترة/الطبقة.
- تبويب رصدات X: keyword / hashtag / account / trend (كما في الخطة الأصلية 2.1 — **يُقدَّم جزئياً هنا** لأنه حرج للشبكة).
- زر «بذر حزمة» للأدمن (يستدعي نفس منطق السكربت) خلف صلاحية `articles.publish` أو أعلى.

## المرحلة 1 — الإشارات الكمية (الدماغ)

> **الهدف:** تحويل الرادار من «تقييم لحظي لكل مادة» إلى «قصص مُجمَّعة لها زخم وصلة قابلة للقياس».
> **التقدير الكلي:** 8–12 يوم عمل · **المخاطرة:** متوسطة (تكلفة متجهات)
> **المتطلب:** المرحلة 0 على staging على الأقل (وإلا التجميع يُظهر ضوضاء بلا مصادر كافية).

### المهمة 1.1 — تجميع القصص (Story Clustering) 🔗

**الفكرة:** مادة الرادار لا تُعرض منفردة بعد الآن؛ كل مادة تُسند إلى «قصة» (`radar_stories`) تجمع كل المصادر التي غطّت الحدث نفسه.

**المخطط (additive):**

```sql
radar_stories (
  id              varchar PK default gen_random_uuid(),
  fingerprint     text NOT NULL,                 -- بصمة مُطبَّعة من عنوان القصة
  title           text NOT NULL,                 -- أفضل عنوان تمثيلي (يُحدَّث مع نمو القصة)
  summary         text,                          -- ملخص عربي (من المحلل لاحقاً)
  status          text NOT NULL default 'active',-- active | archived
  source_count    integer NOT NULL default 1,
  top_news_value  integer NOT NULL default 0,
  saudi_relevance integer NOT NULL default 0,    -- 0–100 (تُحسب في 1.3)
  momentum_score  integer NOT NULL default 0,    -- 0–100 (تُحسب في 1.2)
  first_seen_at   timestamp NOT NULL default now(),
  last_seen_at    timestamp NOT NULL default now(),
  created_at      timestamp NOT NULL default now()
);
-- ربط المواد بالقصة (عمود additive على الجدول القائم):
ALTER TABLE radar_items ADD COLUMN story_id varchar REFERENCES radar_stories(id) ON DELETE set null;
CREATE INDEX idx_radar_items_story ON radar_items(story_id);
```

**المنطق (`server/services/radar/clusterer.ts` — جديد):**
1. بعد الجلب (داخل `cycle.ts` خطوة جديدة بين الجلب والتحليل): لكل مادة جديدة، احسب متجهها عبر بوابة ai-hub (مفتاح AI جديد `radar-clustering` — يُسجَّل في نظام `radar` و`defaults.ts`).
2. قارنها بمتجهات **القصص النشطة** (آخر 72 ساعة): cosine ≥ `RADAR_CLUSTER_THRESHOLD` (افتراضي 0.85) → انضمام لأقرب قصة؛ وإلا → قصة جديدة.
3. عند الانضمام: `source_count++`, `last_seen_at = now()`, تحديث `title` إن كان العنوان الجديد أفضل (أعلى newsValue بعد التحليل).
4. سقوط آمن عند غياب المتجهات: تطابق بصمة الكلمات المُطبَّعة (نفس normalize العربي في coverageGapMatcher) باحتواء ≥ 0.7.
5. خزّن متجه القصة (`embedding` jsonb على `radar_stories`) لتفادي إعادة التضمين كل دورة.

**قبول:** خبر واحد من AP + Reuters + NYT يظهر كقصة واحدة `source_count=3` خلال دورة واحدة. عتبة 0.85 عالية قصدها منع الدمج المتساهل (خطره أكبر من التفكك).

### المهمة 1.2 — الزخم الكمي (Momentum) 📈

**الفكرة:** رقم 0–100 يقيس «هل ينفجر هذا الموضوع الآن؟» من إشارات قابلة للعد، لا من إحساس النموذج.

**المخطط (additive):**

```sql
-- لقطات زمنية لكل قصة (تغذّي السرعة والتاريخ):
radar_story_snapshots (
  id              varchar PK default gen_random_uuid(),
  story_id        varchar NOT NULL REFERENCES radar_stories(id) ON DELETE cascade,
  captured_at     timestamp NOT NULL default now(),
  mention_count   integer NOT NULL,   -- مواد جديدة انضمت منذ اللقطة السابقة
  source_count    integer NOT NULL,
  x_engagement    integer NOT NULL default 0  -- مجموع تفاعلات X المهيكلة (أدناه)
);
CREATE INDEX idx_snapshots_story_time ON radar_story_snapshots(story_id, captured_at desc);

-- تفاعلات X كبيانات مهيكلة بدل لصقها كنص (عمود additive):
ALTER TABLE radar_items ADD COLUMN metrics jsonb;  -- {likes, retweets, replies, views}
```

**المنطق (`server/services/radar/momentum.ts` — جديد):**
1. **هيكلة تفاعل X:** في `xFetcher.ts`، خزّن المقاييس في `metrics` (المزوّدان يعيدانها أصلاً) وابقِ نص الـ excerpt كما هو للتوافق.
2. **لقطة كل دورة** لكل قصة نشطة (الدورة كل دقيقة — اجعل اللقطة كل 15 دقيقة كحد أدنى عبر مقارنة زمنية لتفادي التضخم).
3. **المعادلة:**

```
mentions_per_hour  = مواد آخر 60 دقيقة للقصة
acceleration       = mentions آخر ساعة − mentions الساعة قبلها (قد تكون سالبة)
momentum_raw       = (0.4 × min(source_count/5,1)) + (0.35 × min(mentions_per_hour/10,1)) + (0.25 × min(x_engagement_norm,1))
momentum_score     = round(100 × momentum_raw) — ثم خصم تدريجي للقصص الأقدم من 48 ساعة بلا مواد جديدة (احتضار)
```

4. **تعزيز من وزن المصدر:** انضمام مصدر Tier A أو حساب X-A يضاعف وزن الـ `mention` في المعادلة (ENV: `RADAR_TIER_A_MENTION_WEIGHT=1.5`) — حتى لا تتساوى مدونة صغيرة مع رويترز.
5. النتيجة تُخزّن على `radar_stories.momentum_score` ويُعرض تاريخها من اللقطات.

**قبول:** قصة لها 4 مصادر Tier A و12 ذكراً/ساعة وتفاعل عالٍ تسجّل ≥ 70؛ قصة بمادة واحدة منذ يومين تهبط نحو الصفر. `acceleration` سالبة تظهر في البيانات (لا تُخفى).

### المهمة 1.3 — الصلة المحلية المحسوبة (Saudi Relevance) 🎯

**الفكرة:** رقم 0–100 لصلة القصة بجمهور سبق — محسوب، لا «برومبتي».

**المنطق (`server/services/radar/relevance.ts` — جديد، مفتاح AI `radar-relevance` أو استهلاك `entity-extraction` القائم):**

```
الإشارات (تجمع ثم تُسقَّط على 0–100):
+40  كيان سعودي/خليجي صريح في العنوان (قاموس محلي: مدن، مناطق، جهات حكومية، أندية، شخصيات عامة — ملف data قابل للتحرير)
+25  كيان سعودي في المتن فقط
+20  القصة حاضرة في ترند X السعودي (مطابقة بصمة مع رصدات trend الحالية)
+15  تصنيف داخلي محلي (categorySlug محلي) أو لغة المصدر عربية سعودية
+10  كيان عربي/إقليمي عام
−20  علامات «أجنبي ضيق» (رياضات محلية أجنبية، سياسة داخلية أجنبية…) من قاموس سلبي
```

- يُحسب **مرة واحدة عند إنشاء القصة** + إعادة حساب خفيفة عند انضمام مواد جديدة (القصة قد «تكتسب» صلة).
- استخراج الكيانات عبر بوابة ai-hub؛ القاموسان (إيجابي/سلبي) ملفا JSON في `server/services/radar/data/` ليحررهما التحرير دون كود.
- **مهم مع اتساع الشبكة الأمريكية:** الصلة هي صمام الأمان ضد غرق المحرر بأخبار محلية أمريكية لا تهم سبق — العرض الافتراضي يرتّب بـ `saudi_relevance × momentum` مع فلتر قابل للتعطيل «أظهر الكل».

**قبول:** «الهلال يتعاقد…» ≥ 80 · «إصلاح مجاري في مانشستر» ≤ 15 · قصة عالمية بزاوية سعودية (حج، نفط، تصعيد يمس المنطقة) ≥ 60 · خبر Congres أمريكي بلا زاوية خليجية يظهر منخفض الصلة لكنه **يُحفظ** للتجميع/الفجوات عند التسارع.

## المرحلة 2 — المنتج (الرادار الذي يراه المحرر)

> **التقدير الكلي:** 6–9 أيام · يبدأ بعد استقرار 0 + 1.1–1.3 على staging.

### المهمة 2.1 — إكمال واجهة المصادر ورصدات X + أوزان

- إكمال ما بدأ في 0.5: إدارة كاملة للحزم، الطبقة، الوزن، اللغة التلقائية (أحرف عربية/لاتينية).
- الوكالات العالمية/الأمريكية = «رصد كثيف»؛ المصادر السعودية/الخليجية = وزن أعلى في العرض والتنبيه.
- حالة صحة المصدر ظاهرة بجانب الاسم (أخضر/أحمر).

### المهمة 2.2 — إعادة بناء واجهة الرادار حول «القصص»

- التبويب الرئيسي يعرض **قصصاً** لا مواد: عنوان القصة، `source_count` («٥ مصادر»)، شارات الطبقة (AP/Reuters دخلت؟)، `momentum_score` (شريط + سهم تسارع ↑↓), `saudi_relevance`، خط زمني مصغّر من اللقطات (sparkline).
- فتح القصة يعرض موادها ومصادرها (RSS + تغريدات) وتاريخ زخمها ووقت أول رصد vs أقدم `published_at`.
- ترقية `newsValue` المعروض ليصبح مزيجاً شفافاً: `display = 0.5×LLM + 0.3×momentum + 0.2×relevance` (أوزان ENV) مع إظهار المكونات الثلاثة — لا رقم يتيم بلا تفسير.
- زر «فصل» لقصة دُمجت خطأً (تخفيف خطر false merge).

### المهمة 2.3 — التنبيهات ودورة الحياة

- تنبيه «**قصة تنفجر**»: عندما يتجاوز momentum عتبة (افتراضي 75) مع صلة ≥ 50 → تيليجرام + تعليم عاجل (يُبنى على قواعد `radarAlertRules` القائمة، بلا تغيير عقدها).
- تنبيه «**كسر عاجل من حساب أولوية**»: مادة من مصدر X-A أو RSS-A بـ `isBreaking` أو كلمات عاجلة — حتى قبل اكتمال التجميع (مسار سريع).
- دورة حياة القصة: `emerging → peaking → fading` من اللقطات، تظهر كشارة.
- (اختياري) قناة push للمحررين عبر نظام `push-notifications` القائم.

## المرحلة 3 — فجوات التغطية الحقيقية

> **التقدير:** 3–5 أيام · **المتطلب:** المرحلتان 0–2 مدمجتان في الإنتاج وأرقام المرحلة 1 ثابتة أسبوعاً.

### المهمة 3.1 — ترقية معادلة الفجوات

**المعادلة الجديدة:**

```
فجوة حقيقية = قصة (لا مادة!) تحقق كل الشروط:
  saudi_relevance ≥ RADAR_GAP_MIN_RELEVANCE   (افتراضي 50)
  momentum_score  ≥ RADAR_GAP_MIN_MOMENTUM    (افتراضي 40) أو acceleration موجبة قوية
  لا تغطية داخلية (cosine ≥ 0.82 مع مقالات آخر 7 أيام)  ← كما هي اليوم
```

**التغييرات في `coverageGapMatcher.ts`:**
- المرشحون: `radar_stories` النشطة بدل `radar_items` المنفردة (فختفي تكرارات القصة الواحدة تلقائياً).
- `coverage_gaps` (additive): `+ story_id` (FK), `+ relevance_score`, `+ momentum_score`, `+ gap_reason` (jsonb: قائمة أسباب مهيكلة).
- وزن المصدر داخل المعادلة: قصص مصدرها الوحيد «وكالة عالمية RSS» بلا صلة ولا ترند محلي لا تُنشئ فجوة أبداً.
- **تنظيف:** أول تشغيل بعد الترقية يُغلق (`status='dismissed'` بسبب نظامي `auto-irrelevant`) الفجوات المفتوحة التي لا تحقق المعادلة الجديدة — المستبعد يدوياً لا يُمسّ.

### المهمة 3.2 — شارات «سبب الفجوة» في الواجهة

- كل بطاقة تعرض لماذا هي هنا، من `gap_reason`:
  - «ترند سعودي في X» · «مرتبط: {كيان}» · «{N} مصادر خلال {T} ساعة» · «تسارع ↑{x}/ساعة» · «رُصد أولاً عبر @AP»
- شريطا الحرارة والعُمر يبقيان.
- فرز البطاقات: `relevance × momentum` تنازلياً (بدل heatScore الحالي).
- حالة فارغة محدّثة: «لا فجوات حرجة — تغطيتكم مواكبة لاهتمامات جمهوركم ✅».
